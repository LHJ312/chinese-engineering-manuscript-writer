# 方法说明

本项目首先按中文工程论文的章节科学功能组织写作，再用横向规则检查证据、定量口径、信息用途、自然表达与必要边界。章节功能优先于风格偏好，已确认研究含义优先于压缩。

起草流程为：输入材料→章节与段落功能→必要Plan→局部辅助稿→针对性检查。编辑流程为：原文及上下文→识别实质问题→最小修改→含义保持检查。没有实质问题时保留原文。正文与需要作者确认的内容分开。

Introduction通过已有知识、条件或层级之间未连通的关系形成科学问题；区分CORE、SUPPORTING、IMPLEMENTATION_LEVEL，逻辑覆盖不要求把全部实施任务写入正文。Results与Discussion按分句解释功能及其前提安排，不以连接词、图表主语或句长作机械判断。

横向规则共31条，三级强度为9条LEVEL_1_HARD、16条LEVEL_2_STRONG、6条LEVEL_3_HEURISTIC；Methods实施原则不增加规则数量。规则原编号与合并别名继续保留，避免同一问题重复计数。

公开包从正式runtime清单派生。31条规则块原样保留；章节内容、工作流与Style Card动作保留，仅迁移路径并去除开发依赖。案例统一表示为模式摘要，不含原始稿件、完整正反例或论文长摘录；该内容缩减属于公开化处理，不宣称与原语料逐字等价。

模式摘要不能作为新稿事实，也不能证明某种机制。需要核对外部论文原文时，沿公开书目与页码定位，由用户合法提供上下文；无法取得材料时不得虚构对应段落。历史开发文件与原始语料不作为本包运行依赖。

项目定位为人工辅助写作系统。发布检查验证文件与运行接口，不替代科研验证或稿件作者责任。
