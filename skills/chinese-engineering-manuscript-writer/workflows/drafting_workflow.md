# Drafting workflow

研究材料→识别章节功能→必要Plan→正文→针对性横向检查。只加载路由指定章节；已有有效Plan和已确认材料直接复用，不要求用户重复批准已授权步骤。

1. 确定目标章节、研究类型、输出范围和格式要求。区分作者确认事实、引用认识、原稿、风格参照；风格参照不是新稿事实。
2. 从相应Playbook选择本次必须功能。Introduction先Map及CORE/SUPPORTING/IMPLEMENTATION_LEVEL，逻辑覆盖不要求每项RQ显式列举；Methods说明依赖；Results发现和图表；Discussion解释前提；Conclusion/Abstract正文命题映射。
3. Plan只写需要的信息：主任务、已知命题/锚点、必要数值与条件、前后关系、未确认输入。小任务可用内部短表；不固定段数、句数或各类功能配额。
4. 按Plan起草，但Plan标签和任务配置说明不进入正文。优先写研究认识；新的方法本身可构成贡献。没有已确认机制、数据、文献缺口时不自行推导补齐。
5. 按实际风险选择横向规则：一级处理已定位实质错误；二级先检查合理例外；三级仅作可选提示。必要时读取一个Style Card或成对边界案例，不批量加载资产。
6. 检查数值、指标、引用职责、条件、确定性与原输入是否保持。涉及不同工况/证据系列，不为了闭环合并为同一验证。段内分句可有不同解释层级。

交付用户请求的正文/计划；必要待答项与编辑说明另列。缺失研究输入时完成可写部分，并明确相应部分尚不能作完整终稿；不以移除缺失提示伪装完成。Introduction始终是PLANNING + ASSISTED DRAFTING，不承诺自动稿超过旧稿。

停止在用户任务边界，不自动启动全文、投稿、HOLDOUT测试或后续章节。不存在“必须修改所有段落”或无限生成候选的要求。
