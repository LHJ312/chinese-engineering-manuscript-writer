# Introduction — Runtime Playbook

定位：PLANNING + ASSISTED DRAFTING。沿用六字段Map、八类段落功能、功能路径及Scientific Synthesis；不是自动最终稿生成器，也不要求改稿超过旧稿。

## 输入与Map

输入研究对象、工程/科学问题、作者给定的文献认识和已确认的研究设计。风格参照不能作为新稿事实；仅有文献题名不自动形成已有认识。

| Map字段 | 必要内容 |
| --- | --- |
| RESEARCH OBJECT | 体系/构件、区分特征、比较范围与来源 |
| ENGINEERING / SCIENTIFIC PROBLEM | 具体工况或评价需要、认识困难及影响 |
| ESTABLISHED KNOWLEDGE | 已知关系/能力、条件与来源；按问题而非人名分组 |
| UNRESOLVED RELATION | 对应已知、尚未连通关系、不能直接迁用理由及范围 |
| RESEARCH QUESTIONS | CORE / SUPPORTING / IMPLEMENTATION_LEVEL及回答边界 |
| RESPONSE PATH | 已有试验/分析提供什么信息、为何能回答、回答到哪里 |

K→U连接可标TEXT_SUPPORTED、由明确前提支持的规划推论、REASONABLE_BUT_UNSTATED或UNSUPPORTED。后两类不能用于闭合Gap；“研究少”单独不够，输入池未收录不等于全领域空白。缺项放编辑说明，不输出审计口吻。

## 功能选择

I-ENG建立具体工程问题；I-CONCEPT定义必需对象/概念；I-KNOW组织已有认识；I-BOTTLENECK说明已有能力的限制；I-GAP建立具体未知关系；I-QUESTION聚焦科学问题；I-RESPONSE说明回答职责；I-SCOPE保留必要范围。功能可合并或跨段，不要求八类全部独立成段。

常见路径：工程问题→已有认识→缺口→回应；工程需求→技术瓶颈→改进认识→缺口；现象→已有机制→条件差异→机制问题；评价需要→现有方法能力→对象差别→回答路径。可自定路径，不固定四段，也不能为套路径补新事实。

## Scientific Synthesis与RQ

起草时读取[Scientific Synthesis](scientific_synthesis.md)。核心问题应可由引言辨认；SUPPORTING只在理解切入点确需时显式出现；IMPLEMENTATION_LEVEL原则上进入Methods或内部Plan。逻辑覆盖完整不等于所有任务逐项列举。

## Plan与起草

先列知识单元、过渡关系，再列段落主任务、所需认识/来源、必要条件、前后增量和禁止扩张项。MAP/PLAN状态为PASS、NEEDS_INPUT、NEEDS_REVISION；不以固定RQ数量判通过。已有有效Plan直接复用，不重复审批已授权正文。

有充分输入且授权起草时写辅助稿；发现需要新核心命题时回到Map，不偷偷补出。Gap解释未知关系，Response增加回答方式及能力，不能重复列同一任务清单。Plan配置语言与内部ID不进入正文。

编辑时只修复具体问题，必要目的句、文献条件及正常平行可保留。文献已有因果不能任意弱化，候选机制也不能强化为确定；遵循批准规则的层级与例外。

## 检查与输出

检查问题是否有来源、综合连接是否成立、回应是否在已有能力内、Gap与Response是否各有增量、RQ是否过度显式列举、条件和引用职责是否保留。无实质问题时NO MATERIAL ISSUE。

PLAN任务仅给Map/Plan；DRAFT给辅助正文和必要待答项；EDIT按最小修改交付。参考案例从INT组按需选择，不读取开发报告、旧候选或旧稿作为默认运行上下文。
