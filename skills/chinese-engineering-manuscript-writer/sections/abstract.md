# Abstract — Runtime Playbook

当前人工辅助V1。参考案例按需选择，不默认读取13篇摘要、Claim Chain全库或其他章节。输入只需本稿已有命题和对应位置；没有已建Claim Chain时用最小正文映射，不另建大审计库。

## SECTION PURPOSE

摘要让脱离正文的读者辨认研究对象和问题、回答方式、最重要发现及成立条件。它是整篇论文的压缩论证，不是引言的缩写，也不是把Conclusion贴到方法说明之后。起草以已确认的正文为输入；背景与目的只写到能解释为什么选择该研究问题。

必需输入：目标期刊已提供的格式/字数要求；研究对象与核心问题；Methods的实际比较和回答能力；Results的主发现及关键数字；Discussion中已确认的解释；Conclusion与正文对应；Claim Chain的CLOSED/PARTIAL和必要条件。未提供期刊要求时不猜固定字数或结构式标题，不进行新检索。

## FUNCTION TAXONOMY

| 功能 | 工作内容 | 通常必要性／案例 |
| --- | --- | --- |
| PROBLEM_AND_OBJECT | 界定对象、工况和具体待解决关系。 | 必须可辨认，可省泛背景；M04直接建立计算遗漏问题，M09从荷载调控和机制未知切入。 |
| RESPONSE_AND_SCOPE | 交代研究范式、关键比较及回答能力；数值验证范围在会改变读者判断时保留。 | 通常必要；M02的静力基线与冲击试验，M03末部另交代数值与位移指标的对照。 |
| PRIMARY_FINDING | 回答核心问题的关系或变化，而非“分析了某性能”。 | 必须有正文依据；M09以调控机制收束，M10比较承压/非承压表现。 |
| CONDITIONAL_OR_METRIC_RELATION | 保留改变认识的条件、指标差异、无变化或反向关系。 | 有此类结果时必要；M01的相同能量比较、M02的材料匹配条件、M03的峰值/RMS区别。 |
| QUANTITATIVE_ANCHOR | 用关键数字表达量级、对比、转折或范围。 | 视研究而定；M06分担比例承载机制判断；M04无结果数字仍可报告方法与关系贡献。 |
| INTERPRETATION_OR_CONTRIBUTION | 提炼正文已支持的机制、计算表达或工程含义。 | 按贡献类型出现；M07的协同变形与材料匹配需保留前提。 |
| NECESSARY_BOUNDARY | 保留删去会扩大命题的工况、样本/模型、指标或适用范围。 | 穿插于相应命题，不要求单独免责声明句；M03只明确位移峰值和RMS吻合，不能改成全指标模型可靠。 |

功能可同句合并或跨句，不能强制七句。没有独立机制贡献的论文不补机制句；不因摘要没有“研究较少”就补背景。按论文已有认识写，不能通过词汇强化制造贡献。

## INFORMATION SEQUENCE

通常从问题/对象进入回答方式，再给主发现、关键条件及贡献；这是功能先后关系，不是固定四句式。

- **比较/参数型**：对象与比较问题→最少方法范围→主关系→条件或指标分歧→有依据的含义。M01、M02可提供局部参照。
- **模型/计算表达型**：已有表达缺口→建模或推导及检验方式→新增可表达的关系→比较结果及范围。M04提供数值模型与公式路径。
- **机制型**：具体解释困难→试验观测与计算各自职责→机制认识→受支持的调控或工程含义。M09不需强塞参数数字。
- **多研究环节型**：可先完成一组试验发现，再交代用于拓展的数值方法及验证，如M03；不强制把所有方法挪到同一句。结构式摘要如M06沿用期刊功能标签即可，不据此要求所有论文分栏。

发现之间有条件依赖时先交代条件；不要为了减少字数把破坏模式变化、指标对象或比较基准拆散。背景句删去后仍能辨认科学问题时可压缩，不能用统一背景比例判错。

## RESEARCH-TYPE VARIANTS

| 范式 | 最少方法信息 | 结果重心 | 防止的升级 |
| --- | --- | --- | --- |
| 纯试验 | 对象、加载/对照设计及解释比较所需的关键测量；样本数仅用已知值。 | 破坏、响应及组间条件关系，必要时保留离散或异常。 | 不从少量构件直接推出普遍工程可用性；M02含简化计算仍按冻结分类为纯试验，不虚构FE。 |
| 纯数值 | 模型用途、工况与关键比较；沿用既有验证对象和能力。 | 参数关系、传力解释或计算表达，区分响应指标。 | 不把数值参数组写成新增试验，不把收敛等同全模型准确；M04/M05/M06。 |
| 试验+数值 | 两者分工及连接：哪些指标用于验证、哪些问题由计算扩展。 | 联合回答的主问题，同时保留不对应或未闭环部分。 | 不让“试验+数值”自动证明所有机制；M01/M03/M08/M09/M10。 |
| 理论+数值 | 假设/解析对象、FE对照及既有试验所起的检验作用。 | 解析表达能描述什么，偏差出现在哪类阶段或指标。 | 不把既有试验验证写成本研究新做试验；此变体调用Methods的解析推导接口。 |

参数分析是可叠加功能，不另造研究范式。算法名、本构名、仪器名仅在其能辨认研究贡献或回答能力时保留；不要求列尽软件、网格、加载步骤与所有输出指标。

## QUANTITATIVE RESULT SELECTION

先列已确认结果命题，再为每个候选数字标用途：量级、对比、转折、异常/离散、适用条件或方法辨识。优先保留能改变摘要核心判断的数字；数字数量没有固定上限或下限。

具体检查：删除后是否误认为全程单调、各模式一致、所有指标同向，或看不出效应量级？多项数字重复支撑同一关系且图表/正文已完整承载时，可减少；若每个数字对应不同条件或指标，不能因“数字多”一律删。

M05末部多个参数档位与百分比说明数字密集风险，选择应围绕位移与吸能的关系，不能只留下最有利的降幅。M08同时谈破坏模式转换与尺寸影响，压缩时先区分模式内关系与跨模式比较。M03的峰值最大减震率与RMS平均效果属于不同统计口径，不能拿两个最大值直接替代平均比较。M10的试件数、模型数与承载比各有不同用途，108个模型不是108个试验样本。

候选数字记录`metric / comparison_base / condition / statistic / value / body_anchor / keep_reason`。未知字段不猜填。正文没有必要数字而定性关系已充分表达时不强加数值，也不由摘要重新计算效应或敏感性。

## CLAIM-EVIDENCE CONTROL

逐项建立“摘要命题→正文位置/确认事实→Claim Chain对应→必要条件”。链条CLOSED只表示文本连接已恢复，不等于科学结论经过独立验证；PARTIAL也不等于整篇不可写。只使用本篇已经完成的局部回答，不能补全未完成的设计方法、普适最优或跨工况推广。

Introduction提供问题范围；Methods提供实际做法和比较能力；Results提供观察与数字；Discussion提供已有解释；Conclusion用于检查提炼的一致性。不能把Conclusion作为摘要事实的唯一来源。M03-CC02的普适优化、M09-CC02的设计计算方法、M10-CC01的模型适用边界应继续按原链状态处理。

**区分结果能力与应用用途。** “可为设计提供参考”不自动等于“已证明普遍适用”，不应一律删除；若其前提是明确比较或模型能力，则保留用途。若摘要直接宣称更广工况、整体抗震能力或普适设计可用，须检查对应命题的条件和正文位置。某个CLOSED链不能替代逐项检查；单一大变形指标也不能自动换成工程适用性判据。相应模式已见MODEL的M03指标限定、M06依托桥梁建议与M07材料匹配；这些是章节实施，不新增规则。

调用已批准writing criteria V2（只按所需ID读取，见[规则索引](../criteria/rule_index_v2.json)）：C-01/C-02/C-03管理信息选择与口径；G-02管理论断强度；I-01管理对象/指标；L-01管理必要限定；M-02管理验证范围；N-01/N-02管理测量可恢复性与试验推断；O-02管理参数取舍。H-02的正文映射方法用于摘要检查，但不改其冻结章节范围。这里是章节实施，不新增横向规则。

## FAILURE MODES

| 失败情形 | 可判断触发 | 最小处理方向／保护条件 |
| --- | --- | --- |
| 背景过长 | 多个背景句未增加对象、工况或问题限定，挤掉主发现。 | 留必要问题语境；不按背景字数比例裁切。 |
| 方法流水账 | 软件/步骤/参数连续出现，却无法解释它们怎样回答核心问题。 | 按回答职责压缩；必要试验基线或数值验证不得一并删除。 |
| 数字堆积 | 无法说明多个数字各自支撑哪项摘要判断。 | 按用途选取；转折、异常和比较基准必须保留。 |
| 摘要新增结论 | 某项机制、设计建议或最优性找不到正文确认锚点。 | 返回作者确认或删除未支持表述；不以摘要更有力度为由补造。 |
| 贡献扩大 | 局部指标吻合变成全模型可靠、受限比较变成普遍适用。 | 回到具体指标/范围；M08的“充分验证”不能作为通用固定句。 |
| 机械复制Conclusion | 仅保留结论条目，读者不能辨认问题、方法职责或条件。 | 重新分配摘要功能；必要重复核心发现正常，不为区别结论刻意换术语。 |
| 掩盖指标不一致 | 位移、力、吸能或不同统计量被统称“性能提高”。 | 恢复指标及其条件关系；不得凭统一方向重写正文。 |

## DRAFTING PROTOCOL

1. 确认输入版本、实际研究类型和期刊已知格式，读取已有Claim Chain；记录缺失信息在编辑说明。
2. 建立摘要命题候选表：核心问题、最少回应、已确认发现、数字用途、必要边界及正文锚点。先选回答核心问题的认识，不能按各章篇幅平均分配摘要句数。
3. 选取适合的功能序列；对各句记录增量，允许同句多功能，不强制全部七类显式出现。
4. 生成一次辅助草稿，保持数字、变量、引用意图和确定性；内部标签、待核验状态、Claim Chain术语不得泄漏进正文。
5. 对照下列Checklist人工走查，记录具体位置和最小方向。批准范围内至多一次局部修订；若输入命题未确认，保留作者处理项，不循环生成更强结论。
6. 正文与编辑说明分开交付。不能把自检通过称为自动最终稿认证。每次仅处理用户请求的摘要，不重写参考语料。

## CHECKLIST

- 脱离正文能否辨认对象、工况与核心问题？删除泛背景会损失什么？
- 方法是否说明回答职责，且没有误写研究范式或试验来源？
- 每项主发现能否定位正文或已确认输入？PARTIAL部分有没有被补成完整贡献？
- 每个数字是否有用途，指标、基准、统计口径和条件能否恢复？
- 是否保留了会改变认识的转折、异常和多指标分歧？
- 机制、显著性、最优性、验证与工程意义是否保持原确认强度？
- 是否有条件因摘要独立阅读而需要重述，而非机械移除所有限定？
- 是否只是复制Conclusion，或者为了不重复而改了术语和研究含义？
- 是否存在内部Plan标签、审计口吻或未确认结论进入正文？

以上为章节实施检查；没有实质问题可保留原文，不认证自动最终稿。
