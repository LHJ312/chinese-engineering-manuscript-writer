# Discussion — Runtime Playbook

状态：当前人工辅助V1运行视图。仅整理入口、历史状态与引用，不新增功能或改写规则。案例按需从[精简索引](../examples/case_index.json)选择；无需为本任务加载其他章节。

## 1. SECTION PURPOSE

让读者在已知Results之外进一步理解作用原因、结果之间的关系、解释的条件及工程含义。新增的是理解层次，不是必须新增一个原因句。必要的限定、异常解释和理论比较本身都能形成讨论价值。


## 2. INPUT REQUIREMENTS

输入包括结果锚点及适用范围、作者已确认的解释/假设、支撑这些解释的响应或图表、采用的理论/文献认识、尚未解决的问题。没有解释输入时，输出讨论Plan与待答问题，不以“合理推测”补出机制。

每条解释关联前提、支撑位置、判断强度和边界。缺少前提只说明写作材料尚不能完成论证，不评价原研究真假，也不要求本阶段重算/补试验。


## 3. FUNCTION TAXONOMY

| 功能 | 可观察的认识增量 | 不能替代它的写法 |
|---|---|---|
| MECHANISM | 将响应与已建立的受力、破坏或传播过程相连 | 仅把相关写成“导致” |
| MULTI_RESULT_SYNTHESIS | 多结果共同改变同一解释或评价 | 重复多个结果后只加“综上” |
| LITERATURE_COMPARISON | 在相同或明确不同前提下比较既有认识 | 只说与某文献一致 |
| PARAMETER_INTERPRETATION | 解释参数效应的方向、分支、趋缓或竞争 | 再报一次参数曲线 |
| ENGINEERING_IMPLICATION | 将已有认识对应具体设计对象、指标与条件 | 空泛的研究意义/应用价值 |
| BOUNDARY | 界定认识在哪个工况/阶段/对象成立 | 每句重复同一泛限定 |
| LIMITATION | 说明未覆盖因素如何影响当前解释/推广 | 档案核验进度播报 |
| ANOMALY_INTERPRETATION | 对反例或不一致提出有依据的解释及未决处 | 删除异常或预设它是坏数据 |
| THEORY_CONNECTION | 用假设/平衡/本构关系说明观测或计算结果 | 教材推导与本研究脱节 |

语料的135个讨论单元来自13篇；建模只用其中MODEL部分，DEV用于验证。184个多标签计数不能当作184个独立段落。


## 4. INFORMATION SEQUENCE

可选路径：结果锚点→局部过程→机制条件；指标分歧→共同控制因素→取舍；异常→当前解释不能覆盖的部分→已有候选解释→验证边界；既有模型/理论→本研究差异→前提区别→适用含义。

先决定要解释的问题，再挑证据。M09从损伤与波形转向能量分配和界面传播；M02以材料匹配及是否断裂建立条件机制；M04用部件分担说明计算中不能忽略某贡献。不能要求每种路径都以工程建议结束。


## 5. PARAGRAPH FUNCTIONS

一个讨论段可包含主判断、锚点、解释、条件或反例。判断可概括为“为什么这个现象发生”“为什么两个指标不一致”“这个解释在哪些条件下成立”。仅有共同主题词不能容纳任意旁支；分支只有会支持、限制或改变主判断才保留。

为每段列出相对Results的增量：原因、关系、条件、适用意义或未解决处。锚点结果可以重述，但重述后必须有可指认的推进；输入没有推进就不为了凑Discussion扩写。


## 6. INTERNAL ARGUMENT PATTERNS

F-02按批准V2采用三层功能判别，不按因果词、证据数量或句数判迁移。

| 层级 | 判断问题 | 位置处理 |
|---|---|---|
| OBSERVATION | 是否直接报告已展示响应、比较、阶段或汇总？ | 可留Results；定义本身另记METHOD_DEFINITION |
| PROXIMAL_INTERPRETATION | 是否仅调用此前已明确的定义、装置过程、假设或阶段，帮助理解当前响应？ | 可留Results；不能因有“因为”就删除 |
| MECHANISTIC_INTERPRETATION | 是否需要论证未显示内部状态、选择主要/唯一原因、比较竞争解释，或推出跨结果机制/设计含义？ | 分章时安排讨论功能；合章时明确观察与解释层级 |

判定顺序：先确定句子的功能，再列出全部必要前提并找位置，最后根据稿件分章/合章安排。没有前提位置时记CONTEXT_REQUIRED，不把“物理上合理”当作已经建立。多个图共同报告一个现象仍可是OBSERVATION；一个短句声称“主要原因”也可能需要机制论证。

判定最小单位是命题/分句，不要求整句或整段共用一个层级。已明确“假设只在后期成立”可直接解释前期适用范围；将它称为全部偏差的主要原因是另一项归因，仍需相应支撑。阶段性前提与主要原因归因可同时存在，须分别判断。Plan应保存两项标签，不自动把整段移走。多个候选原因可以围绕一个异常问题并存，但每条需保留原有候选性质和依赖。

M03-P024中“存在间隙—碰撞后起效”可以调用装置过程；若声称所有延迟只由间隙决定，就需要额外论证。M03-P039对瞬时碰撞假设与加速度能力的联系可以就近说明，但其“主要误差来源”不能只凭理想化不同就认定已证明。M01-P033的局部刚度—损伤链保留原有候选性质。M02-P024的双条件机制适合集中讨论，即使原论文把它置于结果相关小节。


机制段内部可按“结果锚点—已有解释—支撑联系—必要条件”展开；若讨论竞争原因，必须输入本来已有竞争解释及判断，不为模板虚构第二种机制。把候选解释移至Discussion不会自动提高证据强度。


## 7. RESEARCH-TYPE VARIANTS

- 纯试验：把破坏、应变、位移等已有观测联系起来；仪器未观测的内部状态不能写成直接观察。
- 纯数值：联系时刻、位置、变量与受力关系；区分模拟揭示的现象与被外部检验的机制，M06缺少独立验证须保留实际边界。
- 试验＋数值：对齐工况、指标和阶段，数值补充过程解释；未对齐的系列不合并成定量验证。
- 理论＋数值：假设—解析趋势—数值偏离—阶段边界，推导本身与其解释用途分开。
- 参数型：写竞争作用、状态转换和条件收益；无一致趋势可保留为认识，不强制参数单调优化。


## 8. CROSS-SECTION CONNECTIONS

每条解释向后连Results锚点，向前回扣引言问题，并向Conclusion交付带条件的已支持认识。M09-CC01连通传播问题、比较模型、能量/波形解释和主体荷载结论；M03-CC01保留加速度边界未被结论完整回收的PARTIAL，不人为补闭环。

边界在改变解释时重复，方法定义已充分且未改变时只交叉引用。已有局限若直接决定验证指标，可留验证段；不能把所有限制统一挪到末尾。


## 9. FAILURE MODES

- 换词复述Results：保留一个锚点，把是否存在解释增量列为作者问题。
- 用更强动词制造机制：对照输入强度，不能把相关或可能升级因果。
- 无关旁支靠免责声明留在主线：检验它是否改变解释；不能改变则考虑省略或附注。
- 因为“讨论”而强添工程意义：必须有具体对象、指标及条件，否则删除空泛结尾。
- 以模型健康/局部对比代替整个机制验证：分清数值检查、实测对照与过程解释。
- 先定原因再挑图：回到完整结果，保留异常及不同指标的分歧。


## 12. DRAFTING PROTOCOL

1. 以引言未解关系和已有Results选2类以内的当前段落任务，不据段数分配机制。
2. 建“解释命题—结果锚点—必要前提—确定性—边界”表。
3. 检查哪些联系是输入明确、哪些为候选、哪些无前提；后者进入编辑问题。
4. 选局部过程、跨结果综合、异常、理论比较或适用边界路径。
5. 输出Plan：主解释、证据ID、推理增量、待补前提、Results接口、结论可接收内容。
6. 撰写时只调用已确认解释；检查是否需要保留一条锚点结果或重复关键条件。
7. 检查跨段是否重复、是否把可能升级确定、是否凭章节移动掩盖范围问题。


## 13. CHECKLIST

- [ ] 相对Results的理解增量能具体指出。
- [ ] 所有解释前提可定位或明确待答。
- [ ] 观察、就近解释和机制论证可区分。
- [ ] 多结果关系围绕同一解释问题，不强拆条件分支。
- [ ] 锚点复述与无增量重复被区分。
- [ ] 工程含义已有正文依据，保留条件及非最优范围。
- [ ] 不因使用“因为”删除正常解释，也不因原文发表而放行强因果。
