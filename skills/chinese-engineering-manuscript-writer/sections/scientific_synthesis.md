# Scientific Synthesis — Runtime Module

用于Introduction规划与辅助起草，不是独立新规则。输入为已有文献认识、研究问题与确认设计。

**ESTABLISHED KNOWLEDGE → KNOWLEDGE TENSION / RELATION → AUTHOR SYNTHESIS → CENTRAL SCIENTIFIC PROBLEM → RQ ROLE**。

先记录已知对象/条件/关系及来源；再指出条件、指标、层级或模型贡献的未连接处。张力不要求文献相互矛盾，研究较少不自动证明具体空白。综合说明这些认识合在一起为何引出当前问题，不从研究步骤反推领域缺口。连接没有前提时保留待作者确认，不补机制或共识。

可采用已经建立的关系模式：遗漏贡献与模型表达、构件能力与体系条件、构造需求与协同受力、观测与机制解释分工、新受力路径与计算表达。按输入选择，不能为覆盖模式增事实；一个段落可只完成部分功能。

| RQ role | 判断 | 引言呈现 |
| --- | --- | --- |
| CORE | 删除后是否失去本篇核心科学关系或改变贡献性质？ | 应可辨认，不必编号或问句；无硬性数量配额 |
| SUPPORTING | 是否解释核心问题的条件、指标或机制分支？ | 必要时显式；也可合入核心问题或回应职责 |
| IMPLEMENTATION_LEVEL | 是否主要是测量、求解、校核、工况实施？ | 原则上留Methods/Plan；方法本身为创新对象时重新按贡献判断 |

Plan可记rq_id / role / central_problem_link / response_anchor / introduction_visibility / reason；visibility取EXPLICIT、INTEGRATED、METHODS_ONLY。该表不进入正文。隐藏实施任务不等于删除研究任务，逻辑完整也不要求逐项显式列举。

每段先区分“前文已建立什么”和“本段新增什么”；Gap写尚未建立的关系，Response只增加回答方式及范围。帮助读者理解对象、关系、条件和方法职责的句子可留；只解释作者怎样分配主线/补充任务的句子留Plan。移除内部ID不等于消除了Plan-to-Prose Leakage。

不得合并无法对应的证据系列为定量验证，不把PARTIAL的未来任务补成完成贡献。只接受作者已确认依据；原稿或文献案例不自动证明新综合。必要时按需查看INT案例或SC-01—03，不默认读取全部案例。
